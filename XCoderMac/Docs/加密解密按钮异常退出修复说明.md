# 加密解密按钮导致 XCoder 退出：原因及修复

日期：2026-10-19。XCoder Mac 版本：0.2.10。

## 原因（来自 macOS 崩溃记录）

用户在“加密解密”界面操作左侧功能按钮后，XCoder 0.2.9 会异常退出。

从 `~/Library/Logs/Newlife.XCoder/2026_10_19.log` 和 macOS `DiagnosticReports/XCoder-*.ips` 已定位：

- **HEX 解码**：普通中文字符串（如“学无先后达者为师”）传入 `SecurityViewModel.HexDecode()` 时，`NewLife.IOHelper.ToHex` 抛出 `System.FormatException`。
- **Base64 解码**：同样输入作为 Base64 解码时，`SecurityViewModel.Base64Decode()` 抛出 `System.FormatException`。
- 上述异常通过 `RelayCommand.Execute` 到达 `Avalonia.Controls.Button.OnClick`，由于没有任何边界捕获，UI 主线程未处理异常引发 `SIGABRT` 并关闭整个进程。

## Mac 侧修复

**仅修改 `XCoderMac/`，不改动 `XCoderAv` 上游实现。**

- `Services/MacSecurityCommandGuard.cs`：为加密解密按钮原始 `ICommand` 套一层委托，保留原 `CanExecute/CanExecuteChanged/Execute` 行为；在同步执行的命令边界捕获非致命托管异常。
- `Views/MacLegacyToolWindow.axaml.cs`：在原加密解密页面放入主窗口之前安装异常保护，视图附着时再次检查；只作用于“加密解密”，不影响其他工具页面。
- 对不合法的 HEX、Base64、RSA 密钥等输入，结果区显示 `【操作失败】输入格式不正确…` 或密钥相关提示，原文和口令保留用于重新编辑。
- 仅输出异常类型到调试日志，不记录明文、密钥或口令。不对底层算法、输出格式或用户配置做任何变更。
- 特别说明：该包装器防止**同步命令异常**导致主线程崩溃；耗时的异步后台任务、底层运行时或原生崩溃需要独立治理，不应推断为已经全部覆盖。

`--smoke-security-buttons` 在真实 Mac 工具标签中验证 32 个命令按钮均已包装，并通过 `Button.OnClick` 执行测试操作：

- 有效 HEX 编码、Base64 编码、SHA256、URL 编码正常返回。
- 非法 HEX/Base64 字符串显示错误，不抛出未处理异常。
- 错误 RSA 密钥显示错误，不终止进程。
