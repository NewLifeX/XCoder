## 1. 强制开发边界（不可破坏）

1. **所有新源代码与修复都只能放在 `XCoderMac/` 目录之下。** 原有 `XCoderAv/`、`XCoder/`、`XCoder-CLI/`、`CrazyCoder/` 等一律不修改。
2. 不创建额外 Git 分支，继续沿用现有 `master`；但开发期间可对 `XCoderMac` 做本地提交和备份。
3. `码神工具.slnx` **已经注册** `XCoderMac`，后续不再改解决方案；工程内新增 .cs/.axaml 会按 SDK 默认规则自动纳入。若增加独立单元测试工程，将其放 `XCoderMac/Tests/`，用独立命令运行，不必修改根解决方案。
4. 上游仅通过 `ProjectReference` 复用，并优先直接使用 NewLife.XCode、NewLife.Core、NewLife.Net、NewLife.Redis、MQTT/Modbus 等组件；macOS 专用 API 实现放 `XCoderMac/Adapters/`。
5. 如上游 ViewModel 的私有方法、Windows 系统调用无法覆写，则在 `XCoderMac/ViewModels/` 中建立独立 Mac ViewModel；**不能为了复用而修改上游**。可以复用协议服务、实体和工具方法，不盲目整份复制。
6. 平台服务建议使用 `XCoderMac/Services/`，Mac 页面 `XCoderMac/Views/`，测试 `XCoderMac/Tests/`，说明和清单 `XCoderMac/Docs/`。适配代码要有必要的单元测试和最小日志。
7. 编译可能更新上游的临时 `obj/`、`Bin/`，这属于构建产物，**不等于允许修改上游源码、项目文件或配置**。所有人工编写的源码与配置只放 Mac 项目目录。
8. 发布、测试也尽量只写 `XCoderMac/bin`、`XCoderMac/obj`、`XCoderMac/dist` 以及用户级 macOS 配置目录；不得把测试数据库数据或真实凭据写进仓库。

## 2. 修复优先级与难度定义

- **P0，先处理**：可能删改用户数据、修改真实网络/设备、严重安全风险、功能本身不能用。相关写操作在修复前应阻止误用。
- **P1，主要修复**：常用工具功能不完整、显著 Mac 兼容问题、可能出现崩溃或无法正常退出。
- **P2，随后完善**：较少使用的工具、表现和易用性、当前缺少硬件/测试环境的专项功能。
- **简单**：约 0.5–2 人天；**中等**：通常 1–6 人天；**困难**：通常 4–10 人天以上。难度主要看跨平台重写程度与验证环境，不以窗口能否打开判断。

## 5. 建议推进顺序（先保安全，再做高复用，最后做专项）

### 第一阶段：P0 安全兜底（建议先做）
- 对 **F02 数据同步、F05 批量正则、F07 文件编码、F14 SSH、F15 Redis、F16 IP、F19 I/O 控制、F24 备份** 做“可用或先安全禁用写入”的处置。禁止无保护地在 Mac 上误触生产数据/设备。
- 建立基础 Mac 服务接口、用户配置目录、关键操作确认和安全测试样例。
- 核心原则：不能安全完成写操作时，应明确禁用，而不是显示成功但实际上没操作。

### 第二阶段：常用、低风险功能快速收口
- **F01 数据建模、F03 RPC、F06 安全工具、F08 网络调试、F09 消息调试、F10 MQTT、F20 图标、F21 文件夹、F22 GPS、F23 地图、F25 语音**。
- 优先使用模拟器/本地回环服务，不需要等硬件。

### 第三阶段：工业设备与网络专项
- **F11 Modbus TCP、F12 Modbus RTU、F13 串口、F19 I/O、F16 IP**。
- 在 `XCoderMac/Adapters/` 共用端口枚举、连接超时、设备权限提示、写入审计/确认。
- 真实串口、转换器、PLC/继电器设备需要现场/台架验证，**没有设备则只能标记为“代码完成、实机待验”**。

### 第四阶段：剩余系统级/特殊功能
- **F04 API 发现、F17 USB 深入信息、F18 声卡切换、F24 手机备份完整实现、F26 梅尔频谱**，以及完整 Release / 公证、跨设备安装回归。

## 7. 验收必须分四档，不再混淆

| 档位 | 判定标准 |
|---|---|
| A 界面可启动 | 编译、窗口实例化、布局、按钮可见 |
| B 核心逻辑可用 | 使用模拟数据/本地测试服务完成实际读写/生成/转换，包含异常测试 |
| C Mac 全链路验证 | 在 macOS 上与设备/第三方服务真实通信，权限、编码、端口、输出均符合预期 |
| D 生产可用 | 安全修复、权限与日志、失败恢复、性能、发布与安装方案全部通过验收 |

**现阶段达到的是全部工具 A 档；不应宣称全部 B/C/D 档完成。** 少数独立工具已实现部分 B 档能力，但仍需系统测试。

## 8. 约定的交付控制

- 每个功能修复新增 `XCoderMac/Views`、`ViewModels`、`Services`、`Adapters`、`Tests` 中相应文件（按需创建子目录），禁止编辑原项目源码。
- 修复完成后更新本文档该工具状态与测试结果，记录运行环境、测试数据及通过/失败。
- 每次交付报告必须包含：Mac-only 改动文件、编译错误数、功能测试结果、未覆盖真实设备项、已知高危依赖告警。
- 不因“窗口通过冒烟测试”而把功能状态标为已修复；不能测试的实机能力必须明确标成待验。
