# XCoder Mac 文件编码页面布局调整（2026-10-20）

## 问题
用户截图显示：第一行“选择 / 扫描 / 转换编码”三个按钮挤在一起，“转换编码”文字被裁切；第二行“后缀过滤”仍为固定宽度 300，导致右侧大量留白，目标编码没有靠最右。

原始布局来自上游 XCoderAv/Views/FileEncodingWindow.axaml：按钮宽度 60 / 60 / 80，第二行采用水平 StackPanel，输入框固定宽度 300。该文件属于上游，不直接修改。

## Mac 专用实现
- 新增 `Services/MacFileEncodingLayout.cs`，`Apply()` 专门对原始布局作轻量调整，**复用原有控件、绑定、事件与命令**。
- `Views/MacLegacyToolWindow.axaml.cs` 仅在工具名称为“文件编码”时调用适配器；不影响其余 25 个工具。
- 第一行保留原始列结构，但设置 `Grid.ColumnSpacing=10`，按钮宽度分别为 `80 / 80 / 118`，并设置最小高度 36、去除按钮原本 2px 左右边距，确保间隔和文字完整。
- 第二行改为四列 `Auto,*,Auto,Auto` 的 Grid：“后缀过滤”标签｜自适应输入框｜“目标编码”标签｜140px 下拉框；输入框取消固定 300px 宽度，编码选择位于右侧。
- 所有修改限于 `XCoderMac/`，不改 Windows / `XCoderAv/` 原始逻辑。
- 当前仅修改界面。扫描、编码识别、GBK/UTF-8 转换以及原文件覆盖安全尚未验收，不能用于证明文件转换逻辑可生产使用。

- 实际截图：`Docs/软件界面/07-文件编码-布局修复.png`。
- 仍需用户在正式界面中确认视觉效果；后续若改版上游窗口结构，适配器会明确报错提示复核。

## 2026-10-20 第二轮：分组及控件间距复核

**用户指出上一次修复不彻底。** 原因：首次适配仅设置第一行按钮间距及第二行列宽，却将“文件编码”加入 `MacLegacySpacing` 的精调排除名单；第一、二个 `GroupBorder` 仍沿用上游 6 的外间距和极小的 Padding，导致两个分组视觉上贴合，按钮与输入框高度不一致。

本次只在 `XCoderMac/Services/MacFileEncodingLayout.cs` 精调原布局，不动上游 `XCoderAv/Views/FileEncodingWindow.axaml`：
- 根 Grid 的 `RowSpacing=12`；文件夹分组和后缀/目标编码分组均设 `Margin=0`、`Padding=12`、`CornerRadius=12`。四个区域间保持实际 12 的分隔。
- 文件夹行 `ColumnSpacing=12`，文本框/三个按钮高 40，按钮宽分别 88/88/124、文字居中，去掉旧布局杂乱的控件 Margin。
- 后缀/目标编码行保持 `Auto,*,Auto,Auto` 的弹性布局，`ColumnSpacing=12`，后缀输入和目标编码下拉均高 40，下拉仍靠最右，标签全部垂直居中。
- 扫描结果区域 `RowSpacing=10`，日志最小高 72，两个多行框内边距 12、圆角 10，避免零间距或贴合。
- 在现有 `--smoke-file-encoding-layout` 基础上增加真实控件 Bounds 的组间距断言（顶部两组、扫描、日志实际间距均不少于 10）、控件高度、圆角和右对齐断言。

**验证**：Mac-only Debug 编译成功，0 错误；`--smoke-file-encoding-layout` 在宽度 1080 / 880 下通过；重新生成并人工查看 `Docs/软件界面/07-文件编码-布局修复.png`，这次顶部两个分组有清晰留白。仅 UI，不执行扫描/转换或覆盖任何文件。

打包：`BuildProjectReferences=false ./XCoderMac/package-macos.sh` 成功生成最新的 `dist/XCoder.app` 和 `dist/XCoder-arm64.dmg`，ad-hoc 签名，未经 Apple 公证。
