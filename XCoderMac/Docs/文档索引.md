## 知识整理规则

1. **只在《项目现状与任务总清单》更新完成度**；其他文档不重复维护互相冲突的功能状态。
2. 新功能/BUG 修复写在对应的专题说明中，标明真实测试范围；不要在 README 累积逐次流水账。
3. 移除的功能入口不应再出现在“当前使用方法”或界面截图导航中。历史评估保留，但醒目标记“已过时”。
4. 窗口能打开、测试截图有内容 ≠ 生产业务已经可用；涉及数据库写入、文件删除/覆盖、IP 网络及设备控制的操作需明确独立验证。
5. 小改动只跑关联模块专项回归；需要完整发行或大范围改造才做全量冒烟/真实端到端。
6. 不把 `bin/`、`obj/`、`dist/`、真实配置、日志、密钥作为知识文件提交 Git。
