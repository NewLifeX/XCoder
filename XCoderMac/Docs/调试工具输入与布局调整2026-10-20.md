# XCoder Mac：RPC / 网络 / 消息调试输入与布局修复（2026-10-20）

## 用户反馈（对应三张截图）

1. RPC API 调试：发送 RPC 请求的 Action 下拉列表启动时为空，原因不明。
2. 网络调试：本机绑定地址的下拉框启动时无选中项，希望选中第一项。
3. 消息调试：连接行的模式选择占据大部分空间，地址输入框极窄；要求紧跟模式、拉长地址，打开按钮靠最右边。

## 原因与修复

### F03 RPC API 调试
- 上游 `XCoderAv/ViewModels/ApiDebugViewModel.cs` 的 `ApiActions` 初始为空；默认 `SelectedModeIndex=0` 即**服务端**。仅切换到客户端并连接远端 RPC 服务时，才通过 `GetApiAll()` 调用 `Api/All` 获取真实 Action 列表。服务端模式/尚未连接时没有远端 Action，空列表属于预期行为。
- `Views/MacApiDebugWindow.axaml` 将旁边文字更新为“Action 列表：客户端连接后获取（服务端为空）”，下拉框悬停提示具体原因；保留手动 Action 输入和上游真实 `ApiActions`、`SelectedAction` 绑定。
- **不制造虚构 Action，也不擅自尝试连接 RPC 服务。** 若客户端连接后仍为空，应结合交互日志排查 `Api/All` 权限、支持情况及调用异常。
- `Views/MacApiDebugWindow.axaml.cs` 新增 DEBUG-only `SmokeTestActionListInitialState()`。

### F08 网络调试
- 上游 `XCoderAv/ViewModels/NetworkViewModel.cs` 构造器已加载 `LocalAddresses`，首项为“所有本地IPv4/IPv6”，但 `LocalAddress` 初值为 `""`，所以 Mac 下拉框没有选择项。
- `Views/MacNetworkWindow.axaml.cs` 创建 VM 后，如果当前地址为空且集合非空，设 `vm.LocalAddress=vm.LocalAddresses[0]`；并保留 ComboBox 的 `SelectedItem` 双向绑定，用户仍可选择某个本机 IP。
- `Views/MacNetworkWindow.axaml` 给该 ComboBox 添加 `LocalBindingAddressSelect` 名称；DEBUG-only 测试首项和手动切换后值同步。
- 默认“所有本地IPv4/IPv6”与原上游 `Connect()` 行为相容：以“所有本地”开头时不绑定特定网卡。

### F09 消息调试
- 上游 `XCoderAv/Views/MessageDebugWindow.axaml` 第一行使用 `Auto,*,Auto,80,Auto,80`，导致“模式”下拉框被拉很宽，而地址只有固定 80 宽。
- 新增 `Services/MacMessageDebugLayout.cs`，在 Mac 宿主内把连接行改为 `Auto,150,Auto,*,110`，列间距 10，地址放在模式后并自适应剩余空间，打开按钮占最右列。
- `Views/MacLegacyToolWindow.axaml.cs` 只对“消息调试”应用适配器；保留上游 TextBox 的 Address 绑定、模式选项和 ToggleConnectCommand。
- **仅 XCoderMac 工程变更；不修改 XCoderAv 上游窗口或网络行为。**

## 2026-10-20 第二轮：消息调试全页面分组及控件间距

**用户明确确认**：此前称“测试调度/消息调度”的工具实际对应此项目 F09「消息调试」。第一轮只修改长地址与最右侧打开按钮，仍遗漏了各区域和控件之间的间距；截图显示连接配置、选项两个分组的边框几乎贴在一起。

**仅修改 `XCoderMac/Services/MacMessageDebugLayout.cs`**，仍复用上游 `XCoderAv/Views/MessageDebugWindow.axaml` 所有原控件和数据绑定：
- 根 Grid 四区（连接、选项、日志、发送）设 `RowSpacing=12`，三组 `Border.Margin=0`、`Padding=12`、`CornerRadius=12`，保证组与组之间真实有间隙。
- 连接行仍为“模式 → 长地址 → 打开”，`ColumnDefinitions=Auto,150,Auto,*,110`，`ColumnSpacing=12`，输入框/下拉/按钮高 40、边距归零，避免高度不一。
- 选项 WrapPanel 统一 `ItemSpacing=12`、`LineSpacing=10`，去掉控件原来的零碎 Margin，参数输入框高 38，与复选框垂直居中；面板宽度不足时允许自然换行。
- 日志 TextBox 去除上下 4 的旧 Margin，设置 `Padding=12`、`CornerRadius=10`、`ClipToBounds=true`。
- 发送行 `ColumnDefinitions=*,100,88`、`ColumnSpacing=12`；发送输入、发送和清空按钮均高 40、边距清零、居中。原发送/清空 Command 不变。
- `AssertLayout` 新增真实 `Bounds` 几何断言：连接→选项、选项→日志、日志→发送三段间隙都至少 10，校验控件真实高度及圆角，防止只更改属性却仍看起来贴合。

**验证结果**：Mac-only Debug 编译 0 错误；`--smoke-debug-input-layout` 在宿主窗口 1050/900 两种宽度通过（RPC Action 空状态、网络默认地址也回归通过）。实际新截图已生成并复核：`Docs/软件界面/09-消息调试-地址栏布局修复.png`。只测试 UI，未建立消息网络连接、未发送数据，尚不能证明真实收发、重连和生命周期。

发布验证：`BuildProjectReferences=false ./XCoderMac/package-macos.sh` 成功，已重新生成 `dist/XCoder.app`、`dist/XCoder-arm64.dmg`；仅本机 ad-hoc 签名，未做 Apple 正式公证。
